# 维护回路与通用class词表

## 1. 每轮反馈
按档位记录范围、证据、已查与未查、有效反查或缺陷样本、质量读数及后续处置。台账保留基础键batch/date/lens/class/fixed/verify，可添加project、project_class、quality与scope；不补造旧分数。

## 2. 通用词表
从下表选择通用class，项目特有内容放project_class。未知码继续报告，不为清零而静默并入已有类别。统计先限定项目和适用范围，历史行保持原文。

| class | 含义 |
| --- | --- |
| `module_not_closed` | 规格里应有、盘上没有（模块/系统/章节/资产整块缺） |
| `claim_without_artifact` | 有声称、无实存（含「文档写了、工程没有」） |
| `stale_artifact` | 被取代但仍像现行的件 |
| `duplicate_truth_source` | 同一事实两处定义且不一致 |
| `broken_reference` | 悬空引用 / 孤儿件 / 改名后未跟改 |
| `numbering_gap` | 编号断号、重号、跳号 |
| `unverified_claim` | 判了「通过」但给不出可复现命令与真实输出 |
| `coverage_gap` | 分母取了产物而不是规格，导致漏检 |
| `scope_overreach` | 检查或修改越过了自己的边界 |
| `sourcing_reuse_without_search` | 溯源整段复述既有清单、零按主题检索 |
| `sourcing_weak_disguised` | 弱依据被写成达标 |
| `ritual_report` | 报告写了但没产生新信息（连续两轮低密度） |
| `process_ossification` | 检查形状 / 方式不随内容增长而变，必做动作因没有落点而漏做 |
| `rule_accretion` | 规范靠不断新增条款增长，没有合并与预算，条款互相重叠 |
| `self_assessment_as_evidence` | 自检者给自己判通过，没有独立复核 |
| `self_assessment_drift` | 自评分与独立复核分按同一契约比对差 >1；保留双方读数与分歧，不等同于没有独立复核 |
| `gate_shift` | 为让本轮过关而降低门槛或改判据/评分契约，未给足适用依据与独立复核 |
| `vanity_metric` | 用字数 / 节数 / 规则数等产出量当改进指标，而不是检出能力 |
| `backlog_rot` | 早期内容按旧判据通过、按现行判据不合格（判据升级或分母翻倍后未回放复检旧货） |
| `spec_ambiguity` | 规格用语**未定义**导致执行者按自己的理解落地（例：「口语化」未定义 ⇒ 执行成方言腔/旧白话，被用户当场纠正） |

## 3. 决策与预算
复发、用户纠正、证据失效或未验证积压触发调查，决定修实现、补证、候选维护或不改并说明原因。不因固定计数到点强制写新规则。
优先修正既有判据；新增默认义务须合并或删去等量旧义务。脚本、探针和例子如果增加默认必做项，同样计入预算。六透镜、九个适用必答问题不靠扩写增加质量。

## 4. 有效verify
记录由谁、用什么命令或观察、读取哪个落点、预期结果与范围；只写“已完成”不算验证。跨执行线交接还需明确实际文件和下游验收判据。

## 5. 自主与授权维护
自主元评审默认一个可独立验证单元；用户授权维护批可以包含多个单元，但各有触发、前后对照、测试、回滚和准入状态。
独立复核只给任务与原始产物，保留真实执行者身份和分歧；无资源时按[quality](quality.md)诚实降级。
状态与通用方法准入见[learning](learning.md)。评分器只验证输入合同与运算，不替人核实证据。
