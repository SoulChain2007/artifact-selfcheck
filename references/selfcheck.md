# 自检方法：从「冻结实况」到「返工件」的五步，以及本轮清单怎么生成

本文件的规则依据：检查活动的检出能力**取决于判据与执行依从性，不取决于条目数量**（Fagan 1976，1503 引；
Haynes 2009 NEJM，5715 引）；反过来说，**清单一旦与内容脱钩就退化成仪式**（Meyer & Rowan 1977，28113 引；
Merton 1940，1366 引）；抽样结论只能对抽样框负责；长上下文注意力会退化，分母大要分片
（Lost in the Middle，1314 引）。所以本文件解决两件事：**每一步的取数动作**，和**本轮该查哪几条**。

## 零、任务画像：动手前先回答四个问题（每轮必做，写进报告开头）

检查的深度与方向不由「习惯」决定，由**任务要求**决定。动手前从任务文本里当场提取四样，
提取不出就写「未提取到 + 理由」，⛔ 不许默认沿用上一轮的画像：

| 问 | 从哪提取 | 产出 |
| --- | --- | --- |
| ① 产物是什么类型 | 任务文本里的交付物名词（报告 / 表格 / 网页 / 代码 / 图 / 设定集…） | 映射到 `domains.md` 证据表的行；表里没有的域按模板补一行 |
| ② 本轮检查档位 | 产物规模 × 失败代价（见下表） | `quick` / `partial` / `full` 之一 + 选档理由 |
| ③ 承重结论有哪些 | 任务文本里的断言句（「覆盖了 X」「性能达标」「与 Y 一致」） | 逐条列出；每条后面都要跟读数或「未验证」 |
| ④ 溯源主题词 | ③ 中结论里的**领域术语**（不是模块名 / 文件名），中英各一份 | 直接喂给 `sourcing.md` 第 0 步的检索式模板 |

档位判据（失败代价 = 结论错了谁受损）：

| 档 | 适用 | 规模 × 代价 |
| --- | --- | --- |
| `quick` | 日常交付：周报、表格、单页网页、短分析、小改动 | 分母小（≤ 20 项）**或**失败代价低（错误可当场改正） |
| `partial` | 一般交付：章节、数据集、专题报告 | 分母中等，或失败代价中等 |
| `full` | 大件交付：模块 / 系统 / 资产包 / 关卡 / 跨多轮攒出的产物 | 分母大，或跨执行者，或失败代价高 |

三档各自的底线与硬闸豁免范围见 `quality.md` 第九节。
⛔ 不许因为「这个任务小」就跳过画像——画像本身只有四行，耗时以秒计；跳过画像 = 本轮检查清单没有来源。

**长任务先读锚再画像**：任务跨多轮 / 分母过换挡阈值 / 产物是多轮攒出来的（世界观、代码库、多章节文档）时，
画像前先读目标锚 `longtask_anchor.md`（与台账同目录）——锚的 ①② 段决定画像第 ③ 栏、④ 段风险登记进入判据生成器 C 路；
锚不存在则第一轮先建锚。目标锚、漂移检测、回放复检见 [longtask.md](longtask.md)。

**按档位加载（成本纪律，2.6.0 加）**：档位决定读多少，⛔ 不许低档位全量加载——references 全量约 1,400 行，
quick 档全读一遍等于查一份周报先看一本手册。判档后只取下表允许的部分，表外文件一律不打开：

| 档 | 允许加载 | 禁止加载（除非触发对应条件） |
| --- | --- | --- |
| `quick` | 本节（§零）+ `quality.md` 第九节 + `domains.md` 中**本产物类型那一行**（用 grep 定位，不整读） | `sourcing.md`（除非画像 ③ 含承重外部结论 → 只读其第 0–0.5 步）；`learning/scaling/iteration/world-probes` 一律不读 |
| `partial` | quick 允许集 + `lenses.md` + `sourcing.md` 第 0–0.5 步 | `learning/scaling/iteration` 只在本轮触发换挡 / 元评审条件时读对应节；`world-probes` 仅世界设定域 |
| `full` / 长任务 | 全量（含 `longtask.md`） | — |

命中禁止行但确需加载时，在报告里写一行「加读 <文件>，因为 <触发条件>」——加载也要留痕，防悄悄全量。

## 一、五步操作流程（每轮都走，不许跳步）

| 步 | 动作 | 产出（缺了就算这步没做） |
| --- | --- | --- |
| ① 冻结实况 | 列盘（文件 / 条目 / 编号 / 计数）、记关键件哈希或 mtime、记当前时间 | 一张实况快照：路径 + 计数 + 取数命令 |
| ② 取分母 | 找**外部规格**（需求表 / 门禁清单 / 不变量编号表 / 资产清单 / 大纲），至少一份来自项目之外（`quick` 档：任务要求文本本身 + `domains.md` 对应行的分母定义，即视为满足项目外规格） | 分母出处（文件 + 行号或编号区间）+ 分母规模 |
| ③ 生成清单 | 按第二节的四路取料，生成本轮判据清单，并写下**选样理由** | 清单 + 每条判据的来源标注（哪一路来的） |
| ④ 跑读数 | 逐条执行，每条给「命令 + 今日真实输出摘要 + 判定」 | 读数行；跑不动的标「未验证 + 原因」，⛔ 不许标通过 |
| ⑤ 对账与返工 | 三栏对账（应有 / 实有 / 悬空）→ 缺口排序 → 返工件（谁做 / 做什么 / 验收读数 / 落点文件） | 对账表 + 缺口表 + 返工件表 |

**顺序不可颠倒**：先读文档再列盘，等于把文档的自称当事实——这是幻觉的第一来源（见 `lenses.md` L1）。

## 二、判据生成器：本轮该查哪几条（防僵化的核心）

四路取料，四路都要过一遍，输出一张「本轮清单」：

| 路 | 取什么 | 每轮至少取 |
| --- | --- | --- |
| A 产物类型 | 本轮产物属于哪几类 → `domains.md` 证据表里对应行的证据来源 | 覆盖本轮**全部**产物类型，每类至少 1 条硬读数 |
| B 上轮台账 | 上一轮 / 最近一轮 `class` 非空的条目 | **1 条针对上轮 class 的同类复检**（同类缺陷会复发） |
| C 风险与口径 | 项目风险登记、用户当场口径、上一轮报告里的「未做项」 | 1 条本轮新出现的风险项（没有新风险就写明「C 路本轮为空，因为……」） |
| D 覆盖补偿 | 上两轮**没被覆盖到**的透镜 / 域 | 1 条从未用过的域证据来源，或补上未覆盖透镜 |

**输出格式（写进报告）**：

```
本轮判据来源：A=<产物类型> 取 <n> 条 / B=<上轮 class> 取 <n> 条 / C=<风险或口径> 取 <n> 条 / D=<补哪条> 取 <n> 条
本轮与上一轮清单的重合度：<百分比>；> 80% 时解释：<分母未变？内容未变？还是没做第②步？>
```

### 防僵化闸门（硬性）

- **重合度 > 80%**：必须写清为什么（分母确实没变、产物没变、上一轮是补做），否则判本轮「清单未重新生成」，
  记 `process_ossification`。
- **B / D 两路取不到料**：允许，但必须逐条写原因；连续两轮 B、D 都为空 ⇒ 触发元评审（见 `learning.md`）。
- **⛔ 禁止**直接把上一轮的清单复制过来改数字。清单是产物，不是模板。
- **深度可以省，透镜不能省**：省了哪一段深度，在报告里写明省的是哪一段（`lenses.md` L6）。

## 三、读数纪律（每条断言都要能被打回重跑）

> **新增 / 修改判据，必须同时交查网记录（2026-09-26 加）**：本 skill 的两半（自检 + 查网）**不许只用一半**。
> 任何"新增判据、收紧判据、换检查方式"的动作，都要在同一轮交一份 `source_intake.jsonl` 新行
> （来源 / 读数 / 支撑句摘录 / 反面检索 / 落点 / 检出器），并跑 `scripts/source_intake.py` 过闸；
> 没有检索记录就改判据 ⇒ 判 `sourcing_reuse_without_search` 的同类失效，**并视同引入未经复核的规则**。
> 依据：BadSkill（arXiv 2604.09378）把第三方 skill 的"看起来无害"列为供应链风险 ——
> 学来的东西默认不可信；AutoWorldBuilder（arXiv 2607.09403）把"缺乏自动化质量保证"列为世界构建三大挑战之一。

- 一条读数 = 一条命令 + 一段真实输出 + 判定。命令要能被人复制后**独立复现**。
- 今天没跑的，不许写「通过」。可以写「上轮通过、本轮未复跑」，但**不能**计入本轮通过数。
- 截断的输出（长列表 / 只看头尾 / 省略号）必须写明截断位置。
- 抽样必须声明：`抽样规则 / 样本量 / 分母 / 结论适用范围` 四样齐全；缺一样即该结论无效。
- 与主张冲突的读数：改主张或派返工件，⛔ 不改读数、不换个说法糊过去。

## 四、对账表与返工件（产出形状）

对账三栏（分母来自第②步）：

```
应有 | 实有 | 悬空（规格有、盘上无） | 多余（盘上有、规格无）
```

返工件每条四要素（缺一件即为不可派）：

```
谁做（角色/线路） | 做什么（可验收的动作） | 验收读数（命令 + 期望输出） | 落点文件（产出写进哪个绝对路径）
```

**跨线依赖必须有落点**：涉及两条以上并行线交接时，除产出者角色与命令外，必须写「落点文件路径 + 落盘判据」，
否则两条线会各自等对方（历史事故：派活只写「A 先提交名单 → B 登记」而未给落点，双方互等，产出为 0；
见 `iteration.md` 第六节）。

### 修补的回归重扫（2026-09-27 加 · 同一缺陷类在同轮里踩了 3 次）

**「发现缺陷 → 修补 → 收工」是错的。** 修补本身会造新缺陷，其中最常见的一类是把矛盾**搬家**：
改了正文，忘了同一份文件的元数据；或忘了**引用本条的别的产物**——
结果矛盾从正文搬到了元数据，机器的字段校验照样全绿，人一读就打架。

⛔ **改任何一条断言，必须同轮重扫三类下游，缺一类即视为未修完：**

1. **本文件的元数据** —— 标题 / 摘要 / 字段值 / 文件内的交叉引用行。
   （例：正文的公式改了，frontmatter 里复述同一公式的那两行没改。）
2. **引用本条的别的产物** —— 所有指向本文的引用行都要扫一遍。
   （例：A 条改了结论，B 条 `rel:` 里还复述着 A 条的旧结论。）
3. **本条定义的数值或集合在别处的越界使用** —— 改了档界 / 枚举 / 阈值之后，必须全库搜一遍：
   有没有别的产物还按旧值说话？新档界有没有留下**落不进去的值**？（本轮实例：把「薄」收成 1 次之后，
   「能发两次」在全库档界里无处安放，直到把相邻档的下界一并改掉才闭合。）

**这三类下游必须用一遍机械扫描来兜底，不能只靠人眼在「本条文件」里看。** 2026-09-27 实测：
一次返工在正文、摘要、字段里把年数全部改成「二十余年」，独立复核也过了，**唯独同一份 frontmatter 里某一行
`rel` 还写着旧口径**；另一处把某个地名改成新写法，而**另外两条产物里仍写着旧写法**。
两次都是「只改了本条、没全库扫旧写法」。故补两条必扫项（每次返工后各跑一遍，把读数写进报告）：

- **旧写法全库 grep**：凡改动一个**数值 / 名字 / 档界**，先记下旧写法，再在**全产物根**
  grep 一次旧写法（不是只搜本条文件），期望 **0 命中**。
- **点名的 id 是否入边**：正文里凡是**点名（如反引号内）引用了别的条目 id** 的地方，
  该 id 必须出现在本条的**依赖或关联边**里；两种边都没有 = 正文与元数据脱钩。
  判归属时用「拿掉它，本条还说不说得清？」——说得清放**关联**，说不清才放**依赖**
  （⚠️ 放依赖会抬升实算深度，属真实结构变化，必须同步复核层号）。

**判定用语纪律**：修补后只能标「**已改**」；标「**已修净**」之前必须有一次独立复核，或一次全库 grep 回归。
未做回归就交付，须在报告「未做项」明写。缺陷状态必须有**三档**：`已修净 / 部分修 / 未修净` ——
不给「部分修」这一档，执行者就会把自己修的统统写成「已修净」。

### 4.12 自检流水：一条命令跑完全部检查器（2026-09-26 加）

**判据再多，没人跑就等于不存在。** 本节是"自检的执行入口"：

```
python scripts/pipeline.py --config <selfcheck_pipeline.json> [--stamp <留痕.json>]
```

配置把每个检查器与参数列成一张表（占位符 `{root} {projectRoot} {ledger} {docs} {mirror}
{reports} {seed} {skill}`），流水按顺序调用并汇总。**三类结果必须分开报**：

| 结果 | 含义 | 该怎么办 |
|---|---|---|
| `CLEAN` | 退出码 0，这轮没发现 | 无事 |
| `FIND` | 退出码 1，**跑赢了但有发现** | 这是**待办清单**，逐条派返工件 |
| `ERROR` | 退出码 ≥2 或抛异常 | **检查器坏了，立刻修** —— 这才是要报警的 |

输出一行可直接抄进报告：`自检流水：通过 k/N（有发现 f，错误 e）`。
外部依据（已过准入）：`pre-commit/pre-commit`（GitHub，现场 **15,595 ★**，pushed 2026-08-17）——
「一个入口按声明顺序跑全部检查」的成熟实现；Eval Pipeline 可靠性（arXiv **2609.00805**，弱依据）。

**实测价值**：流水第一次跑就抓到 1 个 `ERROR` —— 配置把某检查器的位置参数写成了 `--root`
（检查器没坏，是我的调用错了），另有 7 个 `FIND` 全是待办。⛔ 把 `FIND` 当失败 ⇒ 这条线立刻停摆；
把 `ERROR` 当待办 ⇒ 检查器烂了也没人知道。

### 4.11 L6 注意力层：报告的"覆盖面声明"必须与"证据"对得上（2026-09-26 加）

这是透镜矩阵最后补实的一条。旧检查只问"报告里有没有抽样声明"，但**声明可以是空的**：
写了"抽 5 / 池 1270"却一条样本读数都没给，读者无法判断它真抽了还是抄了个数字。
工具：`scripts/sampling_audit.py --reports <报告目录> [--glob ...] [--last N]`

三条机器判据：

1. **声明抽 N ⇒ 至少 N 条逐条读数行**（每行含样本标识〔路径或 ID〕+ 至少一个读数），
   默认容差 20%（`--min-item-ratio`）。缺 = FAIL。
2. **抽样少于池子 ⇒ 必写覆盖面声明**「只对抽样框负责 / 其余 M−N 未查」。
3. **写"穷尽/全量" ⇒ 必须给总量**（池大小或条目总数）；
   ⛔ 且**没有任何覆盖面声明时不许写"全库健康 / 整库无问题"**（越界，判 FAIL）。

当场读数（某项目最近 8 份报告）：7 份 ok、**1 份 FAIL** —— 该批写「本批为穷尽推进」却从未给出规模
（只给了 94→82 这类增量），属**格式层缺口**：声称穷尽就要报总量，否则读不出它"穷尽"了什么规模。
第 40 批是正例：`抽 5 / 池 1270` + 逐条 5 个样本 + 「其余 1265 个文件未查」+ 30 条逐条读数行。

外部依据（已过准入闸门）：PRISMA-LLM（arXiv **2609.11559**）"…the information needed to
**audit these workflows is reported inconsistently**…"（报告规范要求各阶段报数、可审计）；
`LLMs' Classification Performance is Overclaimed`（arXiv **2406.16203**）—— 证据不足时仍给结论是
被实证过的失效模式，对应本节的"越界"判据。

### 4.5 随机抽样 + 逐条引用溯源（2026-09-26 加，每轮至少一轮）

第④步「跑读数」里固定加一次**随机抽样 + 溯源**，用来对抗"总查同几个显眼文件"的注意力偏差：

```
python scripts/sample_trace.py <产物根> --n 5 --seed <固定种子> [--also <它引用的工程根>]
```

对每个抽中的样本，除路径/编号引用外，还要按产出物的域补做一次**命名引用闭合**（见 `domains.md`）：
字段里写出来的实体名必须能命中同名条目。两类结果都写进报告：
① 抽样池大小 / 抽了几个 / 种子；② 每条样本的「引用数 → 可解析数 → 悬空清单」。

⛔ 只抽不溯源 = 没做；只溯源不定量 = 结论不可比。抽到悬空就派返工件（补条目 / 改引用 / 登记历史件），
⛔ 不许把"抽到的这几条没问题"写成"整库健康"。

| 你观察到的现象 | 大概率是哪条透镜失守 | 先补什么读数 |
| --- | --- | --- |
| 报告全篇通过、但一整块东西根本不存在 | L2 分母取自产物 | 换外部规格重取分母 |
