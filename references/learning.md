# 有作用域的自学与回滚

## 1. 四路反馈
保留任务执行、失败与复发、独立复核、用户纠正四路反馈；缺失的渠道明确写出。同时记录保持成功的对照与新缺陷。
项目事实、配置、候选方法和通用规则分别记录。跨项目经验必须给出适用条件，不能因一个项目出现问题就成为所有项目必查项。

## 2. 维护决策
相同适用范围内的复发、低质量读数、无效检出、长期未验证项或用户纠正触发调查。可选择修复实现、提出候选、补证或不改；必须说明理由与证据，不为制造进步而增加规则。
默认自主元评审一次一个可独立验证的变更单元；用户明确授权的版本维护可批处理，每项分别保留根因、测试和回滚点。

## 3. 准入
状态为candidate → validated → admitted → observing → closed；失败可rejected或rolled_back。
通用方法准入需字节或行为上可分辨的新旧对照、不同执行者在最小任务上下文中的复现、以及成功样本不劣于旧版。
只有自评分、同一执行者复跑或没有暴露样本的零复发不能证明通用有效。候选未准入不参与本轮强制验收。已发生的失败不能用N/A或notdone遮盖。

## 4. 回滚
保留旧输入、旧读数和补丁边界；修后另取快照。发现假阳性、漏检或成功对照退化时回滚相关单元并重验受影响结论，不重写旧台账。

## 5. 权限与安装
自学不自动授权改用户产物、验收目标或发布范围。按用户当前授权完成修复与维护；不越过文件权限。
安装清单记录实际路径、角色、版本、来源、哈希、写入结果与宿主加载状态。不按最高版本自动覆盖冲突副本；平台元数据差异与公共正文漂移分别核对。
只有实际写入并复核的目标才记已同步。生成ZIP、创建提交、上传文件与宿主实际启用分别报告。

## 6. 库级维护
按实际范围检查安装漂移、失效判据、悬空引用、版本记录、依赖与准入积压。外部依据需重新核版本和适用条件；旧研究笔记不作为当前事实证明。
模式、评分与独立复核降级以[quality](quality.md)为准，class词表见[iteration](iteration.md)。
