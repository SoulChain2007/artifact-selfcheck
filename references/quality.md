# 3.0 评分合同：检查质量与产物质量分开

目录：模式与硬闸；输入；维度；运算；退出码；台账；迁移。
本文件是新版模式与评分的唯一现行定义。公开包只保留 [2.8迁移摘要](history-v2.8/quality.md)，不包含私人项目原始审计记录。

## 1. 模式与硬闸

| 闸 | quick | partial | full |
| --- | --- | --- | --- |
| G1 需求分母 | 必做 | 必做 | 必做 |
| G2 本轮证据 | 必做 | 必做 | 必做 |
| G3 承重外部结论溯源 | 有外部结论才必做 | 同左 | 同左 |
| G4 工具/断言自证 | 反查已通过断言 | 有效已知缺陷样本与检出读数 | 同左，覆盖承重检查 |
| G5 独立复核 | 可 N/A，须理由 | 执行，或诚实 notdone 并上限 D | 同左 |
| G6 可追溯 | 必做 | 必做 | 必做 |

`external_claims` 必须是布尔值。false 时 G3 可为 `na`，`gate_reasons.g3` 说明无承重外部结论；
不能把有但核不到的外部结论改成 false。用户明确要求查网的任务仍须查网。
G5 的 `false` 表示复核失败，不能用 notdone 掩盖；只有确无复核资源时才能 notdone。
同模型新会话可作为独立执行，但不是独立模型多样性，记录复核者实际身份；禁止自己换口吻扮演复核者。
外部结论不适用不扣分，也不假造查网满分；同时输出有效范围，跨不同范围的总分不可直接比较。

## 2. 新输入与完整 quick 例子

新版输入必须写 `schema_version: 2` 和 `mode`。字段引用指向真实报告、命令日志或原文位置；
脚本只能验证引用结构非空，仍需执行者核实内容。

```json
{
  "schema_version": 2,
  "mode": "quick",
  "artifact_type": "代码",
  "external_claims": false,
  "gates": {"g1": true, "g2": true, "g3": "na", "g4": true, "g5": "na", "g6": true},
  "gate_reasons": {"g3": "只核项目内初始化与运行结果，无外部事实主张", "g5": "本次可逆局部改动按 quick 免独立复核"},
  "g4_kind": "reverse_check",
  "evidence": {"g1": ["需求:条目1"], "g2": ["本轮日志:构建与入口测试"], "g4": ["本轮日志:反查缺配置拒绝路径"], "g6": ["本轮报告:证据索引"]},
  "sa": {"sa1": 4, "sa2": 4, "sa3": 4, "sa4": 4, "sa5": 4, "sa6": 4},
  "sr": null,
  "sr_scope": "无承重外部结论，SR不适用；只对本次变更评分"
}
```

partial/full 的 G4 使用 `g4_kind: "sensitivity"`、`sensitivity_valid: true` 和 `evidence.g4`；
有效须实际读回缺陷输入，且命中目标发现，不是解析失败或崩溃。
G3=true 需要 `evidence.g3`；G5=true 需要 `reviewer` 与非空 `review_evidence`。
G5=notdone 需要 `gate_reasons.g5`；quick 的 na 同样须理由。
G1/G2/G6=true 各须对应 evidence。false 是检查失败；缺失/类型错是输入错误。
需要评分的 SA/SR 半场必须含全部六维，值为 0–5 的有限 JSON 数字；布尔值、数字字符串、越界、NaN 均拒绝。
SR 不适用用 null 加 `sr_scope`，不能填六个 5 分。默认只对适用半场重新归一权重。

## 3. 两半场各六维

| SA | 核什么 | 低分信号 |
| --- | --- | --- |
| sa1 分母 | 用户需求与适用规格，逐项覆盖 | 仅从现有产物倒推需求 |
| sa2 证据 | 本轮版本、真实入口、运行输出 | 编译代替功能；旧测试二进制冒充新源码 |
| sa3 覆盖 | 抽样框、样本量、适用范围、未查项 | 抽样当穷尽，重复样本充数 |
| sa4 检出能力 | 正反对照与有效缺陷样本/quick反查 | 空集合、被跳过的真实分支、崩溃当检出 |
| sa5 处置 | 缺陷有落点、验收和负责人；无缺陷如实记 | 只有建议，无可执行验证 |
| sa6 追溯 | 数字、原文、工具版本、时间与口径可追 | 拼时点、误引二手结论 |

| SR | 核什么 | 低分信号 |
| --- | --- | --- |
| sr1 主题 | 检索与承重结论对应 | 抄缓存、搜错主题 |
| sr2 来源 | 直接相关的一手依据与项目条件 | 用星数/引用数替代技术支撑 |
| sr3 支撑 | 原文/实现位置支持精确结论 | 标题相似但内容不支撑 |
| sr4 时效 | 版本、适用时间与变更 | 旧版当现行版 |
| sr5 覆盖 | 来源覆盖独立结论，稳定权威可复用 | 为新颖度换掉最相关依据或只找支持 |
| sr6 反证 | 对关键假设找局限与反例 | 没有尝试证伪 |

0=未做或证据无效，1–2=关键缺口，3=基本覆盖但有限制，4=较完整有读数，5=范围内充分且可复验。
没有发现真实缺陷不应自动降低 sa4：已知失败样本与成功对照更能测检出能力。
每个分数在报告里给证据；脚本不验证人为评分是否公允。

## 4. 算分、漂移与评级

SA、SR 为适用维度均值；两半适用时默认各 0.5，否则只计适用半场。
`-SelfWeight` 必须是 0–1 有限数。percent=total/5*100。
独立 `review_sa`/`review_sr` 与自评差超过 1 分的维度，实际用复核分重算；
保留自评、有效分、漂移清单，不只打印“复核优先”却仍给自评总分。
任一适用硬闸 false → F；否则 ≥90 A、≥78 B、≥66 C，其余 D。
partial/full G5诚实未做 → 上限D，明确“未经独立复核”，已有客观读数仍是其范围内的证据。
这些是**检查流程**评分，不是产品合格证；有限范围A不能变成整个项目完成。

## 5. 命令与退出码

```powershell
powershell -NoProfile -File scripts/selfcheck_quality.ps1 -Mode score -Scores round.json -Json
powershell -NoProfile -File scripts/selfcheck_quality.ps1 -Mode ledger -Ledger selfcheck_ledger.jsonl -Project project-id -Json
```

schema2 score：0=合同可算且适用闸无失败；1=结果F；2=输入/配置错误。
legacy score：为兼容旧调用，合法计算包括F仍返回0；必须读输出里的 grade 和 legacy 标记，不能作为3.0准入。
ledger：坏JSON、非对象、空台账或筛选后无数据不能返回成功；未知词表报告而不清洗旧记录。

## 6. 台账与历史兼容

旧六键 `batch/date/lens/class/fixed/verify` 保持可读，不补造历史质量分。
新行添加 `project`，需要细分时加 `project_class`，`quality` 保存 mode、schema、范围、证据引用与有效分。
跨项目统计用于发现候选方法，当前项目风险统计用 -Project，不能把别的项目复发算成本项目事故。
旧无schema输入标 legacy；旧无quality行标未评分，不当成0。不同schema/模式/范围的分数不直接画成同口径改进曲线。

## 7. 迁移与独立复核

先保留旧输入与旧读数，再以本版schema2录入新一轮真实检查；不要重写历史行。
复核交给其他执行者时只给任务和原始产物，不泄漏预设诊断；要求其重跑关键证据并尝试反例。
没有独立资源如实标注，不停工、不伪造；合格的受控测试不等同于跨多项目长期有效。
