> 3.0 范围：quick 的 G4 可反查；partial/full 才要求有效缺陷样本。默认规模阈值是启发式，不是外部标准。变异只在隔离副本；检出须目标发现，ERROR不计。阈值改变保留前后样本与回滚。

# 检查方式要随内容规模换挡，并且每轮证明还有检出能力

固定的流程 + 不断增长的分母 = 要么走过场，要么悄悄漏检。所以两件事要一起做：
**怎么查**跟着规模换挡，**查得动查不动**要有可比的读数。

规则依据：检查活动要有速率上限与短清单（Fagan 1976，1503 引）；分母越大越要分片，
因为长上下文注意力会退化（Lost in the Middle，1314 引）；检验手段的检出能力必须被测过
（DeMillo 1978 变异测试，2082 引）；抽样结论只能对抽样框负责。

## 一、深度分档（同一轮里三种深度并用）

- **穷尽**：承重件 + 本批新增 / 改动件 —— 逐条查，分母完整列出
- **抽样**：既有非承重件 —— 写明抽样规则、抽了哪几个、为什么抽它们。
  挑样三类优先：①最久没查过的　②最近改动过的　③被引用最多的
- **随机抽样（2026-09-26 加，与上面三类定向抽样并用）**：定向抽样快、抓热点，但**有偏** ——
  没进这三类的产物可能永远抽不到。所以再加一路**可复现的随机抽样**：固定种子抽 N 个（必须打印种子，
  否则下次没人能重跑同一批样本），然后对每个样本做**逐条引用溯源**：
  抓出路径 / 编号（`docs/NN`）/ URL / ID / `ref:`·`authority:` 行，**逐个尝试解析**，
  解析不了的 = 悬空引用，逐条给「文件:行 + 引用原文」。
  工具：`scripts/sample_trace.py <root> --n 5 --seed 20260926`（通用，任何产物类型；
  产物与它引用的工程是**平级目录**时必须加 `--also <工程根>` 或 `--project-auto`）。
  ⛔ **判据第一次 FAIL 时先看样本再调判据**：本功能首版只搜了 root 与父目录，
  把平级主工程里的 `tools/`、`content/` 全判成悬空（12 条**全是假阳性**）—— 改范围后 0 悬空。
  随机抽样的结论**只对抽样框负责**：写「抽 N / 池 M，其余未查」。
- **登记**：与本轮无关的 —— 只入台账一行，不假装查过

**抽样声明（必写）**：抽样结论**只对抽样框负责**。
⛔ 不许把「抽了 10 个都没问题」写成「全库健康」；要写成「抽样 10 / 分母 89，抽到的 10 件合格，
其余 79 件未查」。分母、抽样规则、样本量、结论适用范围四样缺一即是无效结论。

## 二、灵敏度读数：证明这轮检查还有检出能力

**每轮至少抽检 1 个已知缺陷样本**，看本轮检查能否把它抓出来。两种做法，任选其一：

1. **变异抽检（首选）**：从台账历史 class 里挑 1 条曾经出现过的缺陷类型，
   在本轮要检查的某个件里**构造**一个同类的已知缺陷（只在隔离副本或测试夹具中改动，保留原输入哈希；不得修改正在使用的原件），
   然后照常检查。抓到了 = 本轮对该类缺陷敏感；没抓到 = 检出失效，按 L5/L6 登记台账。
2. **历史样本复检**：从已归档的缺陷件里挑 1 个，确认本轮判据今天仍能把它判为不合格。

**⛔ 变异必须先证「已生效」再做检出判定（第 12 批 CAPA-4 收紧）**：
放入缺陷后，**先证明变异真的进了文件**（diff 行数 / 断言命中 / 读回目标字段），**再**跑检查。
未证生效的样本一律记「**无效样本**」，⛔ 不得计入灵敏度，也⛔ 不得据此判「检出失效」。
**「检出」判据 = 检查器退出码 ≠0 **且** 输出里出现对应规则/门禁的 FAIL 行**——只看退出码会把
「检查器崩溃 / 其他项早已 FAIL」误读成「抓到了」。
依据：某项目 `process_ossification`/`coverage_gap` 连续两批出现「替换因缩进或格式不符而未生效」的无效
变异样本——**先读目标字段的真实格式（缩进、字段名）再构造变异**；本次只收紧既有记录步骤，未新增章节。

记录格式：`灵敏度 = 检出的已知缺陷数 / 放入的样本数`（本轮）+ 每个样本一行
`样本来源 / 放的是什么 / **已证生效（是/否+证据）** / 用什么命令查的 / 抓到没有（rc + FAIL 行） / 已还原（是/否）`。

**判据**：连续两轮灵敏度下降，或连续两轮灵敏度 = 0 ⇒ 强制换检查方式（砍节次、换证据来源、脚本化）。
这是检出能力的证据之一，还须检查相关暴露样本和成功负对照；分数上涨不能替代它。
⛔ 不许用报告字数、节数、规则条数当改进指标（那是产出量，不是检出能力）。
⛔ 变异抽检**必须可还原**：动过的件要留下前后哈希或 diff 记录，报告里写明已还原。

## 三、换挡阈值（项目可改；到期必须换）

阈值是**项目参数**，项目在口径文件里给了就以项目为准；没给时用下面这套默认：

- 某个分母 > **150 个文件** 或 > **500 个条目**：逐条人肉检查换成**脚本批量读数**
  （脚本落盘、可复用，下轮直接跑，人只看差异）
- > **400 个文件**：**分片**——按模块 / 主题切片，每轮深查一片，其余抽样覆盖；
  报告写明本轮深查哪一片、其余怎么覆盖
- 单轮穷尽检查的条目数要有上限（Fagan 的检查速率限制）：超过本域一轮能认真看完的量，
  就必须分片或降级为抽样，⛔ 不许把「扫过一遍」写成「逐条查过」
- 同一项检查连续两轮只输出「无变化」：核是否有相关暴露与有效负对照；证据不足时换更硬来源，稳定有效的回归可保持

## 四、形状可以改，信息不许少

默认节次只是**形状**。允许改形状（加一节、两节并一节、按域换标题），
但必须说明「改了哪几节、为什么」；`SKILL.md` 必答问题清单里的每一条都不许少。

## 五、变更留痕

每次方式变化：报告里写一行
`本轮方式变化：<改了什么> / 触发原因：<阈值、灵敏度下降或哪次失败>`
方式没变也要写一行 `本轮方式变化：无（原因：……）`。
方式变化**必须附本轮质量读数**（`quality.md` 的硬闸结果与两半分数）：没有对照读数时，
「换挡之后是改善了还是只是换了形状」无法判断，这种改动一律按 `rule_accretion` 处理。
需要跨轮对账（换挡前后各 2 轮以上）时，用 `scripts/selfcheck_quality.ps1 -Mode ledger` 读分数趋势，
而不是凭印象。
若改进是通用的（换项目也成立），同时写进本 skill——但受规则预算约束：**加一条要合并或删掉一条**
（见 [iteration.md](iteration.md) 第四节）。
