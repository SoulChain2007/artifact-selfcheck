# 按产物类型选择证据

模式与验收范围由[现行合同](quality.md)决定。表中只列证据渠道，不自动扩大产品要求。

| 域 | 证据与典型边界 |
| --- | --- |
| 代码与库 | 真实构建、调用入口、配置加载、成功与失败输入、退出状态；编译与功能分开 |
| 数据与配置 | schema、记录数、唯一键、范围、外键与转换结果；解析成功不代表语义正确 |
| 数值与平衡 | 单位、边界、资源预算、仿真条件与分布；明确抽样或模型假设 |
| 文档与规范 | 需求覆盖、术语、数字、来源、锚点与跨文档一致性；全文声称须有完整范围 |
| 美术与图像 | 解码、尺寸、透明度、切片边界、命名、清单与实际观感；自动读数不能替代观感验收 |
| 3D与关卡 | 目标引擎加载、比例、材质、碰撞、可达性与运行观察；符合设计的搭接不自动算缺陷 |
| 音频 | 编码、采样率、声道、时长、响度、首尾和循环试听；容器可读不等于听感合格 |
| 流程与UI | 状态可达性、正常与失败分支、回退、资源引用与可见效果 |
| 脚本与流水 | 正确路径、实际执行分支、空输入、协议、留痕、失败状态与调用方解释 |
| 世界设定 | 仅在适用时核实体定义、关系、获得链、概念链与跨层一致；见[world-probes](world-probes.md) |

代码集成应区分构建、逻辑测试、初始化、运行接入和用户可见效果。测试自行构造对象不证明真实产品入口加载了相同配置。
新增域时写清现有证据为何不够，保留相同的需求与证据纪律。
