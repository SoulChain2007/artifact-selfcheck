# 按产物类型换证据来源

透镜不变（六条），**证据来源**按域替换。用法：先定位本轮产物属于哪几类，
再把下表中该行的证据来源逐条跑掉；表里没有的域，按「新增一行」的模板自己补一行写进本报告。

## 证据表

### 代码 / 库
- 证据来源：构建（真实退出码与 error/warn 计数）、单元测试与断言计数（PASS/FAIL 明细）、
  静态检查 / 编译警告、公开 API 的签名对照（文档写的类名/方法名/命名空间 vs 实际声明）、
  依赖版本与目标框架（csproj / package.json / go.mod 里写的 vs 文档承诺的）
- 分母通常是：文档里承诺的类/接口/方法清单、需求条目、不变量编号表
- 该域典型幻觉：类建了但没接进工程文件；文档写的方法签名与代码不一致；
  测试断言恒真；只跑了编译就宣称逻辑正确

### 数据 / 配置（含规则表、清单、CSV/YAML/JSON）
- 证据来源：schema 校验、字段完整性（必填、唯一键、外键指向存在）、
  枚举白名单对齐（规则里出现的枚举值是否都在已定义集合内）、数量与预期待值、
  解析器真实加载（解析失败 vs「文件语法看着对」）
- 分母通常是：schema 字段表、枚举定义表、条目清单
- 典型幻觉：引用了不存在的 ID；同名不同义的两个字段；数字型当字符串存导致比较失效
- **命名型字段的引用闭合（2026-09-26 加，属 L4 的域证据）**：有些字段不是写 ID，而是写**实体的名字**
  （例：`materials: 霜王牙(基底)+霜髓(富)`、`medium`、`carrier`、`cast`、`ingredients`）。
  这类字段必须做一次**反向解析**：把值按 `+ 、 , / 空格` 拆成词、去掉 `(角色)` 括注后，
  每个词都要能在产物里命中一个**同名条目**；命中不了的叫**悬空实体引用**，并统计"被多少条用到"
  作为建条目的优先级。实测价值：某项目 1222 条里有 **94 个名字被引用但无条目**，其中最高的一个
  被 **43 条**引用 —— 这类洞在只看 ID 外键的检查里**完全不可见**。
- **模板默认值检测（2026-09-26 加）**：同一 `(类型, 字段, 取值)` 在同类产物里占比过高
  （经验阈值：≥30% 且 ≥20 条）⇒ 该字段是用模板话充数，不是逐条内容。
  实测价值：某项目 `origin` 有 **295 条同值**、`world_state` 有 **295 条同值**，
  而任何"字段是否必填"的检查都会判它**通过**。
- **下位/被引用闭合（2026-09-26 加）**：最细一层类型（艺术/音乐/文学/习俗/度量…）如果
  **没有任何条目 depends_on / relates 它**，且它自己没声明「本条目为最细层」，就是**下位链断**——
  读起来"有这个工艺"，但落不到"谁在用它"。检查动作：算一次入度，入度为 0 的最细层全部列出来。
- **世界内可达性（2026-09-26 加，世界设定/设定集类产物专用）**：抽一条"世界里的东西"，
  站在**这个世界的人**的角度写出 ≥2 条获得/了解它的**逻辑链**（例：武器 ⇒ ① 某地区经某渠道购买；
  ② 击杀某异兽取某材料自制），再**逐跳**核链上每个节点有没有对应条目、可不可溯源。
  这是唯一能发现"条目自洽但世界不可达"的检查：字段齐全、依赖无环、权威可解析，
  但**没人能获得它、没有产地、没有价格、没有产出源** —— 那条目等于不在这世界里。
- **概念理解链（2026-09-26 加）**：概念类条目（法则 / 判据 / 制度 / 工法 / 术语）除了"定义闭合"，
  还必须有**传授链** —— 这个世界的人从哪儿学到它（学府 / 流派 / 职业 / 法令 / 典籍与它相连）。
  实测某项目抽 200 个世界层概念：定义链 67/70 闭合，**传授链只有 4/70** —— 世界法则是真的，
  但"这个世界的人凭什么知道它"整层缺失。三链 = 定义链（向上到原词）+ 传授链（横向到制度）+ 落地链（向下到实例）。
- **结构审计五问（2026-09-26 加，模板化的"换角度提问"）**：①判据基础设施自检（台账 class ⊆ 封闭词表）
  ②跨条目矛盾（同名实体不同取值）③命名法一致性（slug / 中英混用）④规模自洽（文案数量级 vs 条目数）
  ⑤时序闭合（状态字段是否只出现"现存"）。这五问是从"用户每次怎么找到漏洞"抽象出来的，
  3.0 中①属于通用的词表/检测器自证，按本轮实际使用范围核；②–⑤只在项目确有相应结构与验收要求时执行。不得因历史案例强制所有项目运行世界设定探针。
- **锚点与支撑（2026-09-26 加）**：①引用里的**节锚点**（`docs/NN §X.Y`）要逐条解析 —— 文件在、节不在
  也是断链，文档重构后最常出这种；②**来源支撑性**要抽检（条目名是否出现在被引文件里），
  ⛔ 但必须按类型分档：具名实体才用名字判，抽象条目的名字本就不会出现，只能人工判读。
- **深度四问（2026-09-26 加）**：①**设定 ↔ 机读镜像**逐字段对账（设定说 20 个 op，游戏侧表也必须是这 20 个）；
  ②**反证/边界闭合**（判据必须有"不许什么"，公理与边界自身豁免）；③**一天的生活链**
  （吃住交易纠纷病葬每环有条目 + 世界内落点 —— 落点字段按类型而异，别硬找 nation）；
  ④**分母深度**（整类未枚举=0 只说明每类一个代币；≤2 条列入人工判读，天然单例类型豁免）；
  ⑤**抽样纪律**（没声明覆盖面却说"全库健康"⇒ 越界）。
- **L6 覆盖面声明 vs 证据（2026-09-26 加）**：声明"抽 N"就要能数出 ≥N 条**逐条读数行**；
  抽样少于池子要写「只对抽样框负责 / 其余未查」；写"穷尽"必须给总量；
  没有覆盖面声明却说"全库健康"= 越界。⛔ 只查"有没有声明"是不够的 —— 声明可以是空的。

### 数值 / 平衡 / 参数表
- 证据来源：范围与边界（min/max、零值、溢出、单调性）、单位一致（毫秒 vs 秒、百分比 vs 倍数）、
  求和/占比闭合（各部分加起来是否等于总量）、与规格表的逐项对照、抽样反算
- 分母通常是：设计文档里的参数表 / 目标曲线 / 总量预算
- 典型幻觉：把「表里都有值」当成「平衡成立」；只核了几个显眼数字

### 文档 / 设定集 / 规范
- 证据来源：交叉引用可解析、编号连续无重、术语与术语表一致、与数据/代码的数值一致、
  编码与乱码检查（中文文件务必过一遍编码门禁）、版本/日期行与内容一致、
  **归属判定四查**（判「无人负责 / 缺失 / 盲区 / **建议未执行**」前必做：① 盘上实况——文件在不在
  ② **项目自己的登记文件**——是否已登记未闭合 ③ **设计文档的阶段路线表**——是否计划中尚未到达
  ④ **同文档内的修正 / 澄清段**——grep 该数字或条目在**全文**的出现，看有没有后续修正
  （例：正文写「谓词 10 条」，后文「闭集修正」段已说明实为 18 条 = 8 文本 + 10 边界）。
  只查 ① 会把「已登记」「计划内」误报成「盲区」；漏查 ④ 会把「已修正」误报成「建议未执行」）
- 分母通常是：章节目录 / 条目编号表 / 需覆盖的主题清单
- 典型幻觉：正文引用了被删掉的章节；同一设定在不同文档里两套说法；目录里有、正文里没有；
  把「设计文档已规划的后阶段」或「项目已登记的未闭合项」报成「无人负责的盲区」；
  把「后文已修正的数字」当成「建议没被执行的悬空态」

### 术语表
- 证据来源：每个术语在正文中的出现是否与定义一致、有没有同义异名（一个概念两个名字）、
  有没有定义了两个互指的术语（循环定义）、有没有术语定义了但全项目没人用（孤儿术语）

### 美术 / 图像 / 贴图 / 立绘
- 证据来源：解码成功与真实尺寸、色彩模式与透明通道、色板是否落在项目色板文件内、
  命名与清单一致、与规格里的 anchor / 安全区 / 画布比例对齐、批量件的数量与编号连续、
  同一系列之间的风格读数（关键色、明度范围）是否一致
- 分母通常是：资产清单 / 卡表 / 分镜表 / 尺寸规范
- 典型幻觉：文件在但尺寸不对；命名对了但编号跳号；色板写着「锁定」实际每张都在漂
- 注意：视觉判据要落到**可比对的读数**（尺寸、色值、占比、坐标），而不是「看着还行」

### 3D / 场景 / 关卡
- 证据来源：导出文件可被目标引擎加载、面数/顶点数/材质槽数、碰撞体与可见网格一致、
  可达性（从入口能否走到每个必需区域）、闭环性（有没有进不去或出不来的区域）、
  命名与引用一致、坐标与比例尺一致
- 典型幻觉：场景能打开就算完成，但目标区域不可达

### 音频 / 音效 / 音乐
- 证据来源：容器与编码格式、时长、采样率、声道数、响度（LUFS 或峰值）在规范范围内、
  首尾静音/爆音、循环点可无缝循环、命名与清单一致
- 典型幻觉：格式对了但响度差 6 dB；循环有咔哒声；清单里有 12 条实际只有 10 个文件

### 流程 / UI / 交互
- 证据来源：每个状态可达、每个状态有出口（无死锁）、所有分支都有终点、
  文案与术语表一致、引用的资源/页面/文案 ID 都存在
- 典型幻觉：主路径通了，异常路径（失败/中断/回退）没有出口

### 脚本 / 工具 / 流水线
- 证据来源：在**今天**跑一遍（不是「上次能跑」）、退出码、对输入的边界情况、
  是否 fail-closed（缺输入时是报错还是静默通过）、是否留下有用的日志
- 典型幻觉：脚本只会输出 PASS；缺文件时静默跳过，报告里读成「没有发现」

## 遇到表里没有的域：新增一行的模板

```
### <域>
- 证据来源：<能拿到客观读数的东西，尽量是命令或可量化检查>
- 分母通常是：<这个域的「应有」从哪份规格里数>
- 典型幻觉：<这个域里最容易「看着没问题其实有问题」的地方>
```

新增域条目时，必须同时写清「为什么现有条目不够用」——通常是因为该域有**这一域特有的证据来源**，
而不是因为「这个域比较特殊所以放松要求」。放松要求不是新增条目，是违规。

## 3.0 代码集成补充：测试与产品入口同口径

核主程序真实初始化路径、依赖加载与调用者，而非只核测试自行构建的对象。
将构建、逻辑测试、真实初始化、运行接入与用户可见效果分开；
测试二进制需关联其源码构建版本，配置表加载需要经过真实入口断言。
这一检查需先核实际架构，不要求所有项目使用DLL或Hook。
