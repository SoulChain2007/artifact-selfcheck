# 长任务：目标锚、经验范围与相关回放

目录：目标锚；覆盖；回放；下轮重点。历史机制保留在 [2.8快照](history-v2.8/longtask.md)。

## 1. 保持目标锚

跨轮项目维护 longtask_anchor.md（或项目已有等价记录），与台账关联：
用户核心目标及原话出处；可验收结果；不变量；当前范围/覆盖/风险；项目标识。
已有用户口径可直接复用，不重复索要确认。目标更新须有用户来源，不能按模型评分自动改写。
命令可验证的结果写命令，人机交互与视觉观察写明确步骤与预期，不编造全自动验证。

## 2. 每轮只更新相关状态

读目标锚，判断本轮推进/探索/偏离及验收距离。探索可合法，不能机械连续两轮就停工问同样问题。
真正改变范围、存在冲突或需要用户决策时再提问；已授权工作继续推进。
记录当前变更、相关风险、覆盖分区及未做项。模式针对本次承诺，长任务不自动每轮full。

## 3. 回放检验旧内容

影响本项目的判据改变、共享工具修复、规模显著增长、相关class复发时触发。
优先重验被改变判据影响的旧输入、真实运行入口和旧失败样本；再在未覆盖/长期未查分区轮转抽样。
最早20%是历史策略，可作为一个抽样框，不能永远只抽最早分区；记录样本池、选择规则、样本与未查量。
只有发行版本变化、与本项目无关的方法变化时无需机械回放全库。
检查器缺陷波及的旧读数标失效待重验，不能仅靠“上轮通过”顺延。

## 4. 把读数变成下轮重点

相关class复发 → 调查根因并进风险登记；低分 → 查对应证据链；分母增长 → 调整抽样/分片；
覆盖长期不动 → 解释卡点并推进实际验收。没有相关暴露样本时零复发不能关闭缺陷。
成功对照也要保留，防止新判据只抓住旧错误却误伤正常输入。
跨模式/分母/评分schema的数值不直接比较；给可比样本和工具版本。

最小读数行：项目 / 当前输入版本 / 本次分母与实际覆盖 / 模式 / 灵敏度样本有效性 / 目标关系 / 下一轮重点。
