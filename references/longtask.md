# 长任务模式：目标锚 + 回放复检（任务跨轮生长时，自检跟着长）

进入判断（任一成立即进入长任务模式，并写进本轮任务画像）：

- 任务明确跨多轮 / 多会话（批次制、派活制、阶段制）
- 分母预计或已经超过换挡阈值（见 `scaling.md` 第三节）
- 产物是多轮攒出来的：世界观 / 设定集、大型代码库、多章节文档、数据集

退出：任务宣告完成那一轮走 `full` 档总检；目标锚归档，⛔ 不删。

要防的三类失效（既有机制管不到的那部分）：

1. **目标漂移** —— 内容越写越多，慢慢不再服务最初的核心目标；而每轮的任务画像只看当轮文本，看不见全程。
2. **早期内容腐烂** —— 判据随任务生长逐步收紧，第 1 轮的内容是按第 1 轮的判据通过的；
   判据升级后没人回头验旧货 ⇒ 任务越后期，库里「历史合格品」占比越高，整库质量读数被旧货抬虚。
3. **分数空转** —— 自评分打了、台账记了，却没被翻译成「这个任务下一轮该查什么」；
   `learning.md` 的元评审触发是通用阈值，不管单个长任务的重点排序。

## 一、目标锚：长任务的核心目标落盘（第一轮建立，每轮必读）

文件：`longtask_anchor.md`，与本轮台账同目录（项目另有规定从其规定）。四段：

| 段 | 内容 | 纪律 |
| --- | --- | --- |
| ① 核心目标 | 一句话，**从用户当场口径原文抄** | ⛔ 不许自己概括发挥；用户口径变更是唯一合法修改来源 |
| ② 验收读数 | 怎么算完成：命令 + 期望输出（能跑的那种） | 写不出命令的验收 = 未定义，报告里标出 |
| ③ 不变量 | 任何一轮都不许破坏的约束（引擎版本 / 命名空间 / 规则预算 / 风格锚） | 每条配一条「今天能跑」的检查命令 |
| ④ 范围登记 | 当前分母规模 + 已覆盖 / 未覆盖分区 + 风险登记（台账里累计 ≥2 的 class 进这里） | 每轮末尾更新一次 |

每轮 `selfcheck.md` 第 0 步任务画像**先读锚**：画像第 ③ 栏承重结论对照锚的 ①②，
第 ② 栏档位判据加一条「距验收读数还差多少」。本轮判为长任务而锚不存在 ⇒ 第一轮动作就是建锚。

**目标漂移检测（每轮一条读数）**：本轮产物与锚的关系三选一：**推进 / 无关 / 偏离**。
无关与偏离不禁止（探索合法），但必须在报告写明；**连续两轮「无关」** ⇒ 向用户确认目标是否已变。
目标变了 ⇒ 改锚，三件套：旧锚文本 + 新锚文本 + 用户口径出处，⛔ 不许悄悄改锚——
锚的每次改动在锚文件末尾留痕一行（日期 + 改了哪段 + 口径出处）。

## 二、回放式复检：用现行判据验早期内容

触发：判据有升级（`changelog.md` 落地任何一行）**或**分母较锚建立时翻倍的当轮起，每轮从
**最早 20% 的产物**里抽 ≥1 件，用**本轮现行判据**完整复检一遍（命名 / 格式 / 引用 / 数值 / 域证据）。

- 检出 ⇒ 记 `backlog_rot`（已入 `iteration.md` 封闭词表），派返工件；
- 抽样复用 `scaling.md` 的固定种子随机抽样，抽样框指向早期分区，工具可复用 `sample_trace.py`；
- 分母还小（< 50 件）时豁免，写明「早期分区尚小」；
- 回放结论同样只对抽样框负责：「复检 N / 早期分区 M，其余未查」。

依据：判据只会越来越严——现行判据是通过的最低线，早期内容按旧判据通过 ≠ 按现行判据通过。

## 三、分数 → 下一轮针对性（自评分不许空转）

每轮报告第 11 节之后加一行「下一轮针对性」（三句话以内），从本轮读数直接推出：

| 本轮读数 | 下一轮针对性动作 |
| --- | --- |
| SA1 / SR1 ≤ 2 | 锚的 ④ 范围登记或画像 ④ 主题词不准 ⇒ 先修锚 / 修画像再查 |
| SA4 连续两轮 ≤ 2（灵敏度失效） | 判据对当前规模过时 ⇒ 按 `scaling.md` 换挡 + 换更硬的证据来源 |
| 某 class 累计 ≥2 | 该缺陷族进锚的 ④ 风险登记 ⇒ 后续每轮判据生成器 C 路必取它一条 |
| 分母翻倍而检查方式未变 | 记 `process_ossification`，按换挡阈值强制升档 |

与 `learning.md` 的分工：learning 管「什么时候改判据、怎么验改动」（改方法），本节管
「这个长任务的下一轮该查什么」（用方法）。两节冲突时以 `learning.md` 的触发条件为准。

## 四、长任务每轮报告加一行（规模读数）

```
长任务读数：分母 <N>（上轮 <M>）/ 深度档 <quick|partial|full> / 灵敏度 <k/n> / 锚覆盖 <已覆盖分区>/<总分区> / 漂移判定 <推进|无关|偏离>
```

- 分母翻倍而灵敏度读数没换证据来源 ⇒ `process_ossification`；
- 锚覆盖长期不动（≥3 轮）⇒ 在报告里向用户问一次「目标是否还成立」，不许闷头继续。
