# 溯源复核：按承重外部结论检索

目录：适用性；取来源；复用；准入；记录。历史做法保留在 [2.8快照](history-v2.8/sourcing.md)。

## 1. 先判断是否需要外部证据

外部规范、API行为、论文结论、时效事实、未经证实的技术判断需要检索或直接读取权威原文。
用户要求查网时执行查网。纯项目实现事实应先从源码与运行读数核对，不靠论文替代。
没有承重外部结论时记录 external_claims=false、理由与SR不适用；不能把核不到伪装成不适用。
新增通用方法若只源自本轮实验，标现场方法候选，给实验范围；不能编造外部背书。

## 2. 如何取来源

1. 从精确结论提取领域术语和检索式，优先一手来源；需要时用中英两种检索补覆盖，不强求所有查询双语。
2. 官方规范/原始实现核精确版本行为，研究论文核实验论断；来源层级随断言类型确定，论文不自动高于官方实现。
3. 读支撑原文或文件位置，记录URL、访问日期、适用版本。每源摘录保持简短且遵守版权，不机械按“两行”截取长段。
4. 对承重假设搜索局限、反例或不适用条件；精确官方API契约可直接核其错误/限制章节，不为了形式额外找博客。
5. 相关独立结论分别核；同一权威规范可支持多条，但逐条给具体位置。不能用“来源真”替代“支持这句话”。

没有网络且外部事实无法直接核验 → 未验证/来源受限，不能凭记忆补版本、URL、引用数或star。
来源的新颖度和star不是正确性证据。项目明确给阈值则记录它是项目政策；无阈值不要自行捏造数值。

## 3. 跨轮复用与历史事实

稳定、相关的一手来源允许重复；记录本轮核对的版本/内容是否仍适用，不再硬性要求换掉50%来源或每轮新增来源。
需要多样性的是独立证据覆盖和反证，不是站点计数。确有来源变更再加新来源。
论文/仓库的旧star、引用数属于访问当时的历史读数，不写成现在的数字；不承重时无需为它每轮重新取数。
[prior-art](prior-art.md) 是历史检索线索，未经本轮原文核对不得继承“已核实”的结论。
原历史记录不改写，新的复核记录追加。

## 4. 外来方法准入

`source_intake.jsonl` 每行保留字段：source/surface/reading/quote/counter/target/verdict/detector。
verdict 只允许 adopt/weak/reject。真实未读到的读数写 N/A+原因；quote 是实际支撑句或明确“自创：无外部支撑句”。
自创方法外部依据标weak，但可在用户项目中以明确实验范围验证；实验有效不等于普遍理论已证实。
detector 对 adopt 必须可执行或有明确可复验观察步骤；拒收也留记录，避免反复污染。

```text
python scripts/source_intake.py --ledger source_intake.jsonl --json
```

0=结构合规，1=内容发现，2=输入/读取错误。空台账、null字段、非对象、非法verdict不能成功。
结构合规不证明引用真实、方法正确或已获准；准入仍须 [learning](learning.md) 的旧失败回放、成功负对照与独立执行。
无新外来方法时不运行一个空台账来“证明没问题”，记不适用。
自主元评审一次一个变更单元；用户授权的版本维护可批处理，但每项单独记录证据与回滚。

## 5. 最小记录

结论编号 → 精确来源位置 → 原文/实现支撑 → 版本/访问时间 → 适用条件与反面结果 → 采用/弱依据/拒收。
区分原文、推断和项目政策；工具返回的搜索摘要不代替读原文。
本版修改的技术依据可核 Python subprocess 官方文档与 PowerShell比较运算符文档；
它们只支持退出码/类型行为，不支撑“本skill一定更有效”的结论。
